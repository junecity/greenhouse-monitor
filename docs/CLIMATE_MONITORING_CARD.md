# Climate details and home-screen widgets

Open **Dashboard → Climate details** on the central greenhouse gauge. On an Android home screen, long-press a free area, open **Widgets → Greenhouse Studio**, and select a greenhouse or an individual sensor. Existing pins keep their selections. **Settings → Display** also offers pinning on supported launchers.

The widget asks the launcher for five columns and two rows. At normal text size a slot at least **300 × 120 dp** can show the reference layout: temperature and humidity tiles, a six-hour chart beside them, and a bottom strip for condition, outside, target, dew point and the reading time. A tall pin can stack its sections; smaller slots and larger system fonts prioritize legibility. Launchers decide the actual cell dimensions and keep the size of existing pins. Long-press an existing pin and drag its side handles to fill the row. Climate details keeps the panel, readings and graph in place as the feed loads or reconnects. A new live observation briefly highlights the endpoint. The launcher redraws its graph as readings arrive.

## What the readings mean

- The card observes the same enrollment, greenhouse, stored sensor inventory and SQLite history that the app already uses. A standalone phone reads its own collector. A paired phone reads the authenticated server snapshot and its enrollment-specific history. Losing the network retains eligible cached readings with their time; signing out clears access. No new backend route, permission, or database migration.
- The H5179 collector polls Govee over HTTPS, using its existing stored API key for [discovery](https://developer.govee.com/reference/get-you-devices) and [device state](https://developer.govee.com/reference/get-devices-status). The UI, server heartbeat service and scheduled worker share one collector. A dedicated server also collects with its Dashboard closed, at its configured interval. An enrolled standalone phone with a pin uses its existing monitoring service for Govee and Bluetooth readings; if that service is unavailable Android can schedule a shorter collection attempt. Successive automatic callers reuse very recent observations. The provider returns its latest state; a successful collection time is not proof the thermometer took a new physical measurement at that instant. Failed reads aren't new observations. BLE uses the existing local collection path. A viewer's snapshot interval remains configurable per greenhouse.
- **LIVE** means the selected feed has a recent, available observation. **DELAYED** marks aging data, and **OFFLINE** marks unavailable or expired data. There are distinct setup, permission and error states. The update time refers to the readings, not when the widget was drawn. Rendering never triggers temperature alarms. Manual retry uses the app's existing sync, with a one-minute retry cooldown per enrollment and greenhouse.
- The whole-greenhouse tile and Dashboard use the latest valid readings from assigned online sensors in the past ten minutes. They use floor-plan weights for positioned sensors, or an equal average when none have positions. The update time is the oldest contributing observation. A single-sensor pin shows that sensor’s reading. Once current readings expire, the card can show a labeled cached value.
- The six-hour chart uses the same ten-minute window at each historical observation and plots at most one point per five-minute interval. It uses the currently saved sensor positions, since the app records readings with timestamps but does not keep a history of placements. A staggered report can update the average while its peers’ observations are still valid. If the reporting group changes or more than ten minutes pass, the chart starts a separate segment. During a delay, the line ends at the last observed point and leaves the rest of the timeline empty.
- The chart labels its first and last values when both use the same sensors. Otherwise it labels the latest value. Fewer than two points produces “Not enough history.” The hourly rate needs at least four observations spanning thirty minutes in the latest continuous segment.
- **Outside** uses the current weather service's temperature for the configured ZIP and its own timestamp. It can be unavailable while indoor readings are live. **Target** is Energy's learned overnight temperature for this greenhouse when it has enough eligible data; it is not the alarm limit. A reading within 1°F of the target is shown as at target. **Dew point** requires fresh, valid indoor temperature and humidity. A dash means unavailable, including on first use.
- Local observations and authenticated server snapshots trigger a launcher redraw. A paired phone’s existing background monitor checks the server’s upload timestamp and schedules a fetch when it changes. It retries transient failures. A widget configured for a specific remote greenhouse or sensor waits when another source is selected. The unconfigured current-greenhouse selection follows the active source.
- Placing or configuring a widget also requests current data. The widget can refresh the outside temperature for its configured ZIP without opening the weather screen. Reading age, weather age and sync time are distinct. [Android schedules widget updates](https://developer.android.com/develop/ui/views/appwidgets/advanced#update-frequency) and can defer background work while the phone sleeps; a disconnected or force-stopped phone cannot guarantee live delivery. A redraw does not by itself poll Govee or create a new observation.

## Alarm colors

A red widget with an **ALARM** badge means a sensor it monitors has an active alert. A greenhouse widget stays red until its last relevant alert clears. A widget pinned to one sensor responds to that sensor alone.

On a paired client, a critical temperature alarm stays red until you press **Stop alarm**, even if the sensor has recovered. Stopping it offline clears that phone’s widget and queues the acknowledgement. On a standalone or server phone, a local temperature or humidity alert clears when a fresh reading returns within the configured limits. A delayed feed can still show an active alarm, and the reading time remains visible.

## Checking on a Galaxy A71 and Pixel

1. Update both phones in place. On the collecting phone, verify a sensor and its reading under Devices. Tap the Dashboard gauge and note the greenhouse, reading and time.
2. Open the same greenhouse on the paired phone after a successful sync. Check the reading time against the server. Repeated syncs with no newer readings should not move the timestamp forward.
3. Place a widget on each home screen. Resize from narrow to wide/tall. Try a single sensor pin and Celsius; the selection and unit should survive reopening the app. If your launcher cannot give the pin enough space, use the Dashboard card for the chart.
4. Temporarily disconnect the viewer from the internet. Open Climate details and check that cached readings are marked unavailable or stale. Reconnect and retry; confirm a new reading appears after the server supplies it.
5. Check at larger Android font sizes and with animations disabled. Without enough accumulated history or overnight training, the graph or target can legitimately be absent.
